# Research v2 methods

This is an implemented exploratory apparatus derived from `RESEARCH_REALIGNMENT.md`, not a preregistered confirmatory study. Historical observations retain the original protocol. The public release must distinguish functional equivalence from sustained performance and implementation from measured evidence.

## Architecture and stable APIs

B uses seven component roles: shell, toolbar, table, asset row, summary, chart and details. All explicitly use OnPush. Angular 14 retains NgModule bootstrap. Angular 15–16 use standalone components with immutable touched-record publications and dependency-aware imperative selectors. Angular 17+ uses real per-entity signals, per-row watch/selection signals, UI state signals and computed order/summary/chart/selected-entity derivations. It does not use a revision-only signal. Signal inputs are deliberately not required; the common component interface remains stable `@Input`.

Symbol order/search/sector filtering read immutable identity metadata, not changing price signals. Price sorting reads prices and invalidates correctly. Watch filtering reads membership only while active. Each row consumes its own entity and membership; the table consumes ordered IDs. Selected details consume the selected entity. Aggregate work still reduces the entire market; it is not magically O(1). Both imperative and signal designs compute the index once per tick and reuse it for history.

Canonical engine update modes remain unchanged. In-place mutation and changed-record replacement publish copied touched entities to the UI. Full-array replacement publishes every clone, even unchanged values. Default reference equality is retained. The cost of these copies is inside the apply-call timing. Zero-workload events still advance logical time/history; they are not no-state callbacks.

Stable built-in loops and conditionals begin at Angular 18. Stable explicit zoneless scheduling begins at pinned 20.3; 21–22 use framework defaults. Angular 16 signal previews and 18–19 experimental zoneless providers are excluded. The same-version Angular 22 M4 arm changes the Zone import/provider while keeping signal state, graph, flow and OnPush fixed. It studies the scheduler/polyfill treatment, not pure scheduler internals. The separately instrumented replica distinguishes public `ngDoCheck` hook counts from actual template-evaluation counters, alongside selector evaluations and DOM mutation records. The failed initial hook-only diagnostic is retained: hook traversal alone did not establish view refreshes. No private Angular internals are used.

The native C adapter uses the same portable imperative graph on all versions, preserving generated bootstrap, scheduling providers and implicit change-detection defaults. The B architecture is therefore not silently substituted into C. All configured defaults and scope adaptations are inspectable. The default test targets remain generated; their existence does not establish common-contract test coverage or comparable runner performance.

## Correctness and provenance

An independent Node oracle starts from the committed canonical fixture JSON, applies event arithmetic independently, and derives visible order, index, advancing count, percentage, volume, chart coordinates and selected price. It never calls application selectors or `MarketEngine.apply`. Existing engine-based regression checks remain complementary. The browser gate exercises every mode, asynchronous delivery, zero work, clamping, all-record changes, filters, empty states, watch state, selection, sorting, timer pause/reset, node identity and focus. Explicit focus restoration is a shared new-architecture behavior; legacy sources are not changed.

Build records include source, lock, configuration and emitted artifact hashes. Pilot metadata records source commit/dirty state, harness hashes, Chrome binary/version, Node, OS, CPU, memory, viewport and locale. Uncontrolled governor, power, thermals, cache and background load are stated as uncontrolled, never inferred to be stable. Clean recorded source improves provenance but does not provide OS isolation. Compilation verification durations are not accepted build-time experiments.

## Measurement and uncertainty

The original runtime campaign described here is a pilot. The separate [confirmatory protocol proposal and runner](CONFIRMATORY_CAMPAIGN.md) require explicit researcher approval. Each independent block uses a fresh browser process per treatment; treatment order rotates over a complete balanced cycle. A block is the sampling unit. The fixed six-tick pilot is deliberately too short for stable p95 inference or capacity claims. Three ticks warm the same update path, followed by reset. Full-oracle validation occurs outside the measurement window; per-step gates check logical tick presentation. The Node oracle advances expected state between ticks; that harness work is included in the completion window and can affect cadence. Separate correctness runs check full derived state after each test event. The pilot reuses their acceptance only when source and emitted-artifact hashes match, then repeats full initial/final numeric validation in every fresh process.

Presentation opportunity spans apply through two animation-frame callbacks; synchronous apply-call duration is secondary. Lazy computed work may occur after the apply call, so apply duration alone cannot establish a speedup. Serial lossless backpressure means no independent producer, queue or dropped-traffic capacity inference. Lateness is retained even when final state is correct. The pilot currently exercises B sparse mutation updates without timed interactions; interaction scenarios in the legacy harness are not retroactively v2 evidence.

Report run-level p50/p95 and paired differences across complete independent blocks. The exploratory percentile bootstrap resamples block pairs with a fixed seed. With fewer than two complete pairs, uncertainty is unavailable. With two pairs it is extremely unstable; a narrow interval is not evidence of significance. Missing/rejected blocks remain visible. Do not pool across experiment IDs, manifests, environment sessions, workload policies or historical tracks. Main-campaign primary metrics, selected comparisons, duration, precision target, multiplicity treatment and sample-size decision remain pending researcher approval.
